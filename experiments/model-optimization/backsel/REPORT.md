Plain statement: **on this benchmark the mechanism costs more wall time
(+25-40%) and slightly more RSS, and forwards rise by k/n.** The conditional
model is a 128-wide MLP whose backward is a negligible share of the step;
what backsel adds (a second forward of k rows, a second kernel evaluation
for `g_i`, Python selection) outweighs what it removes (the backward and
graph of n-k rows). The differentiated-samples column is the only currency
that improves, by 2-16x, and it is worth nothing here because graph memory
is not the binding constraint (RSS ~780 MB is torch itself).

**Where it can pay off: only where the differentiated sampler dominates
cost -- SD scale, not this MLP.** In the SD pipeline (`systems/AUDIT.md`
sec. on `run_mlgd_f.py`), each sprinter variation in the graph costs ~3
UNet+ControlNet forwards (nested checkpointing recompute) plus the backward,
at `variation_batch_size = 1`, and the variation graphs are the dominant
memory term. THEORY.md sec 6 gives the estimate: cost ratio
`(N + 5k) / (5N)` in forward-units, i.e. ~0.5 at N=6, k=2 and ~0.3 at
N=100, k=8, with graph memory scaling as k instead of N. That is the setting
in which backsel should be re-evaluated (with the non-legacy protocol, and
with `clust k>=4` or `uni`, not `is`, as the first rule to try).
